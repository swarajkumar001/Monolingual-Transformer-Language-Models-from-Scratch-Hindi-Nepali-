\begin{abstract}
\noindent
This is a standalone Phase 1 report for \textbf{Nepali as Model L},
companion to \texttt{phase1\_report.tex} (Hindi / Bhojpuri). It follows the
same structure but is a separate document because Nepali runs on a
different pipeline (\texttt{nepali/scripts/}, stage-based S00--S14) with a
different data layout than the Hindi/Bhojpuri cleaner, so its own numbers
are not simply insertable into that report without changing what each
figure measures. Nepali's final corpus is \textbf{635,204,333 tokens}
(127.0\% of the $\sim$500M planning target), clearing both of the
pipeline's absolute lane targets (manual $\geq$100M, downloaded
$\geq$400M) and the assignment's 20\% manual-collection floor
(26.41\%, token-weighted). Nepali supersedes Bhojpuri as the graded
Model L; Bhojpuri's own work is kept intact in the repository and in
\texttt{phase1\_report.tex} as a complete, working record, not deleted.
\end{abstract}

\section{Data Collection}
% =====================================================================

\subsection*{Manual vs.\ downloaded, as defined for this pipeline}

Same course ruling as Hindi/Bhojpuri: ``manual'' means content requiring
active per-source collection work (API/XML-dump parsing, HTML scraping
with site-specific extraction, OCR) as opposed to downloading an
already-corpus-ified public dataset. Unlike the Hindi/Bhojpuri report's
char-weighted manual share, Nepali's split is \textbf{token-weighted} --
the pipeline tracks words/tokens per lane past S03, not characters. This
is a methodology difference worth being explicit about if the two reports
are ever compared directly.

\subsection*{Why the manual lane is dominated by one source}

\texttt{news\_onlinekhabar} alone supplies 91.6\% of manual tokens. This is
a real, measured constraint, not a collection shortcut: OnlineKhabar has
the largest scrapable Nepali news archive among the manual sources
configured, and \texttt{nepali/scripts/auto\_grow\_and\_tokenize.py}'s
growth loop bumped its \texttt{target\_words} in \texttt{sources.yaml}
(capped at 260{,}000{,}000 words) specifically because it was the only
manual source with enough real headroom to close the gap to the 100M-token
manual floor. The other manual sources (Wikipedia, Wiktionary, Wikibooks,
smaller news sites, one OCR document) are genuinely smaller pools for
Nepali than their Hindi equivalents.

Nepali's pipeline is stage-based (\texttt{nepali/scripts/s00\_doctor.py}
through \texttt{s14\_corpus\_stats.py}), sharing the same
\texttt{corpuslib} code as Hindi's own Nepali-parallel pipeline copy

\subsection*{S08 deduplication}

Removed 52{,}084 of 2{,}178{,}418 documents: 2{,}350 exact duplicates,
49{,}734 near duplicates (MinHash/LSH, \texttt{num\_perm=100, bands=20,
rows=5, shingle\_size=5, threshold=0.55}). 21{,}273 cross-lane duplicate
pairs were found (the same content collected via both the manual and
downloaded lanes); all 21{,}273 were resolved in favor of the manual copy,
per the pipeline's priority-to-manual policy.

\subsection*{S09 decontamination}

Removed 17{,}111 train documents that matched held-out (val+test) content
above threshold 0.55, preventing train/eval leakage at the content level
(not just document-id level). A rescan afterward found 0 remaining
matches.

\subsection*{S10 lane balancing}

The train pool's raw manual share going into S10 was 23.27\%. Rather than
loosening any filter to inflate it, S10 trimmed the \textbf{downloaded}
lane (589{,}223 documents dropped, manual lane untouched) to bring the
ratio to 27.42\% -- safely above the 20\% floor without manufacturing
volume.

\fig{10_lane_balancing.png}{Lane balancing: manual share before/after S10.}{nepali-balance}

\section{Tokenizer}
% =====================================================================

\subsection*{Algorithm and sweep}

BPE (SentencePiece), swept at vocab\_sizes [5000, 6000, 8000, 10000] per
\texttt{nepali/configs/tokenizer.yaml}, matching the course-TA ruling
capping recommended vocab size to the 5{,}000--10{,}000 range given the
$\sim$25M-parameter model budget (the same ruling applied to Hindi's own
vocab\_size=8000 choice).

\section{Cross-Language Check (Nepali vs.\ Hindi)}
\label{sec:crosslang}
% =====================================================================

Run via \texttt{scripts/check\_nepali\_hindi\_overlap.py}: every one of
Nepali's 1{,}918{,}265 final documents (train 1{,}520{,}000 + val
199{,}428 + test 198{,}837) had its \texttt{dedup\_key} (sha1 of
whitespace-collapsed, punctuation-stripped, lowercased text -- identical
algorithm to \texttt{scripts/clean\_lib.py:dedup\_key}, computed fresh
since Nepali's own pipeline doesn't store one) checked against the full
set of 704{,}101 dedup\_keys already computed for Hindi's cleaned corpus
(\texttt{hindi/data/cleaned/metadata.jsonl}).

\textbf{Result: PASS -- 0 shared dedup\_keys.} No document is shared
between the Nepali and Hindi corpora. Full run took 467.7 seconds. This
addresses the spec's ``do not share documents across corpora'' requirement
for the two languages that are actually part of the graded submission
(Nepali vs.\ Bhojpuri was not checked, since Bhojpuri is superseded and not
part of the final two-language submission).

\section{Limitations}
% =====================================================================

\begin{itemize}
\item \textbf{Manual share is token-weighted, not char-weighted} (see
\S2), unlike the Hindi/Bhojpuri report. Character-level lane tracking was
never added to this pipeline; token-weighted is the honest number
available.
\item \textbf{Cross-language check covers Nepali vs.\ Hindi only}
(\S\ref{sec:crosslang}), not Nepali vs.\ Bhojpuri, since Bhojpuri is not
part of the final two-language submission.
\item \textbf{Top-token frequency (Fig.~\ref{fig:nepali-freq}) is top-50
only}, not a full Zipf distribution, since \texttt{evaluation\_report.json}
only retained the top 50 and reproducing the full distribution would
require re-encoding the entire corpus.
\item \textbf{Manual-lane concentration}: 91.6\% of manual tokens come
from one source (OnlineKhabar). This is disclosed in \S2 rather than
smoothed over.
\end{itemize}
